# PROMETHEUS — Recovered Canon Snapshot
Date: 2026-10-05
Status: requirements/canon recovery; implementation evidence remains UNKNOWN unless separately evidenced.

PROMETHEUS = PROtotype & Technology Research, Experimentation and Development — The Fire-Bringer. PROMETHEUS is a first-class specialist App and professional R&D environment, not a replacement CAD/engineering engine. It provides a coherent project environment above curated proven engines while higher intelligence fills genuinely novel automation gaps.

PROMETHEUS and DAEDALUS are companion specialists. Their boundary is closed; do not invent a Mechanical-vs-Electrical split.

Canonical R&D lifecycle: DISCOVER → INVESTIGATE → CONCEIVE → EXPERIMENT → PROTOTYPE → PROVE → DEVELOP. Professional development supports Objective → Design → Analyse → Build/Configure → Test → Results → Iterate.

UI/UIX: compact macOS/Lightroom-like professional workspace, not an Office ribbon. Top workflow bar mirrors major stages; hideable/customizable left panel exposes detailed functions. Simple / Advanced / Expert is one compact mode control. Project surfaces include Overview, Prototypes, Experiments, Tests, Requirements, Files, Research, Results, History, Components/Automation and Settings. Development surfaces include Design/Build/Test/Analyse/Iterate, 3D/CAD and technical views, inspector/evidence/revision/candidate state.

Storage: regular files and large objects stay in the native filesystem. Lightweight structured sidecars/manifests (txt/XML/XMP-like where appropriate) hold metadata, relationships, provenance, state and instructions. Do not introduce a complex database merely for ordinary project content.

Execution: PROMETHEUS owns a direct domain execution layer for Python, appropriate shell/CLI, Tool Adapter actions, Blender Python, FreeCAD Python and configured local automation. Deterministic Actions/Recipes are a critical core subsystem; repeatable known operations execute without AI. Reuse proven existing/open-source engines rather than recreating them.

Intelligence: higher intelligence is not the deterministic core. Native/local/user-selected intelligence may satisfy suitable requests. Novel engineering/code-generation gaps can escalate through established BIFROST connectivity to Codex/cloud compute. PROMETHEUS supplies domain/R&D context and validates returned results. BIFROST supplies connection/routing/session/cloud infrastructure. All of this should occur behind the scenes rather than forcing the user to configure AI tasks.

Interoperability: objects may expose Mechanical, Electrical, Data, Power, Thermal and Software/API interfaces for dependency/impact tracking across specialist Apps. PROMETHEUS↔DAEDALUS uses a structured transfer package; the physical container is secondary (ZIP or similar is acceptable) and a custom extension/name identifies the workflow. Packages may carry metadata, references, provenance, evidence, manifests, assets and executable/instruction recipes for Blender, FreeCAD and supported tools. Media/XMP is an analogous established pattern, not a requirement to force XMP onto engineering data.

BIFROST: PROMETHEUS remains standalone with a thin BIFROST connector/plugin. Reuse BIFROST plugin/connection architecture. Do not duplicate connection management, identity/routing, Codex session management or cloud-compute plumbing inside PROMETHEUS.

Development evidence: current Mac audit found no standalone PROMETHEUS project directory/repository before backup staging. Build/test/package/physical state is UNKNOWN, not PASS.

Outstanding engineering investigation: Codex is to investigate and find appropriate proven solutions for the Actions subsystem and unresolved implementation gaps. Selection follows existing-capability-first and preserves local-first/offline deterministic operation where practical.
