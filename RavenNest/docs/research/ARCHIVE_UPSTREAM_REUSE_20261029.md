## Upstream source evaluation — links are actual project sources/docs
1. **IIAB core + menu**: https://github.com/iiab/iiab, https://github.com/iiab/iiab-menu and https://github.com/iiab/iiab-admin-console/blob/master/roles/console/files/help/ContentMenus.rst . Verified official descriptions show customizable libraries, menu.json and menu-item definitions, mobile/desktop layouts, automatic content discovery, multilingual labels and content references. **Reuse data/UX patterns**, not IIAB Linux hotspot service inside Workers.
2. **IIAB content packs**: https://github.com/iiab/iiab-admin-console/blob/master/roles/console/files/help/InstContent.rst . Quick Pick bundles ZIM/Kolibri/OER2Go/map content, installs packages as explicit jobs, tracks status, and handles removable media. **Reuse named collections, source manifests, optional download/install jobs** only after rights, storage and consent are verified.
3. **Kiwix Serve**: https://github.com/kiwix/kiwix-tools/blob/main/docs/kiwix-serve.rst . Genuine HTTP ZIM library browser and fulltext search. **Reuse optional local/cross-device reader** over an explicitly paired and authorized connector; this native HTTP daemon is NOT a Workers module and must not auto-open LAN ports. Safari reading is supported.
4. **OpenList Worker**: https://github.com/OpenListTeam/OpenList-Worker and https://doc.oplist.org/guide/installation/worker . Existing Cloudflare Workers+D1 browser storage gateway; docs advertise multiple driver backends. Its existing MCP endpoint https://doc.oplist.org/guide/advanced/mcp uses a raw Authorization token (not Bearer), stateful session, protocol version 2025-11-25. **Candidate for scoped file manager reuse, NOT drop-in identity/MCP protocol implementation** until license (AGPL-3.0), auth and cross-tenant isolation tests are done.
5. **Filestash**: https://github.com/mickael-kerjean/filestash and https://www.filestash.app/docs/guide/mcp-gateway.html . Existing storage-agnostic web UI, numerous protocols, RBAC and MCP gateway; needs independent server/runtime hosting, not native Cloudflare Worker. **Alternative** if multi-protocol backend is funded/authorized; not deployed here.
6. **Chrome WebMCP tools**: https://github.com/GoogleChromeLabs/webmcp-tools/ and https://github.com/GoogleChromeLabs/webmcp-tools/tree/main/webmcp-evals . Actual official upstream polyfill, Inspector and deterministic browser smoke tests. Progressive enhancement for browser agents. **Never treat it as ordinary Safari functionality or a substitute for server-side scoped MCP**.
7. **Cloudflare MCP Portal**: https://developers.cloudflare.com/cloudflare-one/access-controls/ai-controls/mcp-portals/ . Aggregates downstream MCP servers with per-server OAuth and user access policies; NOT a human library UI, not a backend database nor substitute for the original RavenNest app. Current private portal has no confirmed MCP endpoints of its own.
8. **Cloudflare Remote MCP auth**: https://developers.cloudflare.com/agents/model-context-protocol/protocol/authorization/ ; https://developers.cloudflare.com/agents/model-context-protocol/guides/remote-mcp-server/ . Actual OAuth authorization server and stateless protected resource server (Workers OAuth Provider), explicit consent and per-tool scopes, bearer verification and denial. **Preferred basis for independent remote MCP**; no live endpoint implemented here.
9. **Archived source `iphone-mcp.url`**: actual text contains `https://glama.ai/mcp/servers/teddyoweh/iphone-mcp`. The upstream uses macOS Xcode/USB WebDriverAgent/XCUITest to remotely control physical iPhone UI and messages, not a read-only file connector; iPhone control requires elevated privileges, and Glama's tool-inspection entry does not demonstrate a working cloud deployment. **Reject as default RAVENnest local-file bridge**.
10. **Preserved alternate source URL files**: `mcp-server.url` -> https://www.mux.com/docs/integrations/mcp-server ; `downloader-mcp.url` -> https://glama.ai/mcp/servers/CarlDog/downloader-mcp ; `mcp-arr.url` -> https://glama.ai/mcp/servers/aplaceforallmystuff/mcp-arr .
