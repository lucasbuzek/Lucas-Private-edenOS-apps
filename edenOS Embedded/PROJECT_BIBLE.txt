PROJECT BIBLE — edenOS Embedded
Target baseline: 0.1 / Samsung SM-T110 (goyawifi)
Updated: 2026-10-03

IDENTITY
edenOS Embedded is the lightweight Android-compatible embedded EDEN profile for constrained/reused hardware. The first physical target is Samsung Galaxy Tab 3 Lite 7.0 Wi-Fi SM-T110/goyawifi, ARMv7, ~1 GB RAM, 1024x600. It preserves the working Android hardware/runtime layer and normal APK compatibility while adding EDEN system/service capabilities.

CURRENT GOAL
Build the first custom edenOS Embedded testbed as a useful always-on household edge appliance that remains a normal usable tablet. Primary server workload is SKALD; secondary lightweight household server is NOSTOS; BIFROST Embedded manages device/service/connective state; SMB provides managed file access.

AUTHORITY / GOVERNANCE
Global AppDev authority remains ~/edenOS/Projects/#appDev Bible/. This file is project-specific authority only. Recover before recreate; existing capability first; functionality before presentation; preserve LKG. GENERATED != IMPLEMENTED != BUILT != TESTED != VERIFIED != RELEASED; UNKNOWN != PASS. AUTO continues safe available work until milestone or genuine unavailable dependency. Canonical pipeline: REFERENCE -> BASELINE -> IMPLEMENT -> STATIC VERIFY -> ENVIRONMENT VERIFY -> REGRESSION VERIFY -> PACKAGE -> PACKAGE VERIFY -> PHYSICAL GATE -> PROMOTE.

PLATFORM
Preserve Android/Samsung hardware support rather than replacing the OS with conventional Linux for 0.1. Retain Package Manager/APKs, display, touch, Wi-Fi, audio/media, storage and power stack. No Google Play dependency. APK import/sideload required. Third-party APKs remain ordinary Android apps and are not rewritten/themed/wrapped by EDEN.

FIRST APK SET
Independent APKs: edenOS Home; BIFROST Embedded; SKALD Android representation/control; NOSTOS Android representation/control; edenOS Files. Do not make one monolithic APK. Prefer platform APIs and tiny deterministic dependencies; avoid heavyweight modern UI frameworks on this target. All must support ARMv7 and 1024x600.

DEVICE MODE
TABLET MODE restores normal tablet power behavior. SERVER MODE keeps configured headless services available with screen off while preserving normal tablet use when woken. BIFROST supervises service state/restart/reboot behavior. Server Mode is not Kiosk Mode. Desired user control is Samsung/Android Quick Settings where safe; exact SystemUI integration is deferred until installed Android/build is physically identified.

EXPERIENCE MODE
System-wide EDEN-owned UI profile: Standard (default), Simple, Child, Accessible, Kiosk. Presets may control complexity, text/control scale, density, navigation, labels, motion, contrast and advanced-control prominence. Simple is optional and is not synonymous with age/disability. Third-party APK UI remains unchanged.

BIFROST EMBEDDED
BIFROST = CONNECT / KEEP / RESOLVE. It manages device identity, service/App discovery, real running/stopped/unknown state, measurable health, start/stop/restart, representation endpoints, storage/network/resource status where available, logs, package/version/update state, APK compatibility/Package Manager handoff, remote management representation and Server Mode supervision. REGISTERED != WORKING. It must not absorb SKALD or NOSTOS domain logic.

SKALD
SKALD is the primary server workload and remains the standalone Media & Entertainment/media-content specialist. Android UI is a lightweight representation/control surface over the authoritative headless service. Preserve established SKALD functionality including unified library, Movies/TV, browse/search, identification, metadata, artwork, subtitles, downloads/ingest, jobs/activity, review, storage, settings/diagnostics, watched/progress, collections, background library management, direct/remote serving, Travel Packs, Daily Episodes and modular providers where recovered.

SKALD EMBEDDED MEDIA CONTRACT
MKV is commonly the source. Inspect streams; obtain/apply metadata/artwork/subtitles; remux compatible sources to Apple-compatible MP4/M4V using video stream copy only; preserve compatible audio, chapters and track metadata where possible; verify output before atomic promotion; retain source until verification succeeds. NO VIDEO TRANSCODING on SM-T110. Outcomes are REMUXED, SOURCE PRESERVED, or TRANSCODE REQUIRED/deferred. Reuse mature FFmpeg/ffprobe tooling with a verified ARMv7/API-compatible build. Prefer microSD for Downloads/Processing/Library. SMB may expose managed Incoming, Downloads, Library/Movies and Library/TV paths but never credentials/internal DB/runtime secrets/private config/temp.

NOSTOS
NOSTOS is the EDEN Home & Household specialist and on this target runs as a lightweight headless household-information server. Its established responsive Web UI remains the main management interface. Core domain: household/family information; sites/structures/spaces; possessions/assets/inventory; provisions/supplies; chores/tasks; maintenance schedules/records; household documents/records; utilities where applicable; history; search; settings; multi-user access where established; local-first persistence; backup/restore. Android APK is a lightweight local representation over the same service/data, not a competing implementation.

NOSTOS EMBEDDED EXCLUSIONS
For this profile do not add Home Assistant, Homebridge, Matterbridge, Node-RED, HomeKit, Matter, MQTT, smart-home automation, alarm/security/camera processing or AI merely because broader NOSTOS concepts may support them elsewhere.

EDENOS HOME / FILES
Home is a lightweight launcher/status surface and consumes rather than owns service state. It launches EDEN and normal third-party APKs and exposes Device/Experience modes. Files provides lightweight access to internal user storage, microSD, Downloads/Documents and permitted SKALD paths; reuse mature SMB/network providers rather than recreating filesystems.

OPTIONAL TABLET APPS
Prefer existing lightweight third-party APKs for browser, IMAP/SMTP email, office compatibility, PDF/EPUB, text/Markdown, gallery/media player, archives and basic utilities. Capability on disk must not imply resident RAM use. No Play Store requirement.

RESOURCE PRIORITY
Server Mode resident set should be kept approximately to Android core + BIFROST Embedded + SKALD headless + NOSTOS headless + SMB + essential network/storage. SKALD has workload priority. Measure actual RAM/CPU/storage/startup/throughput/UI responsiveness/stability; never invent measurements.

REMOTE MANAGEMENT
BIFROST manages machine/service state; SKALD manages media; NOSTOS manages household information. Normal administration should not require SSH; ADB/SSH remain expert/development/recovery paths. SMB must not be directly exposed to the public Internet.

CURRENT BUILD MILESTONE
Produce installable ARMv7 APK candidates: edenOS-Home.apk, BIFROST-Embedded.apk, SKALD.apk, NOSTOS.apk, edenOS-Files.apk. Each must build on macOS, install independently, have truthful metadata, render at 1024x600, avoid ARM64/Google Play/AI/cloud requirements, and report UNKNOWN/UNAVAILABLE rather than fake backend success.

PROJECT STORAGE CONTRACT
The project itself lives directly at ~/edenOS/Projects/edenOS Embedded/ on the Mac and in the PRIVATE development repository, not the official release repositories. EitriFactory is the builder/governor, not the owner of project artifacts.
App-specific source/definitions belong with their respective projects: BIFROST -> ~/edenOS/Projects/BIFROST/; SKALD -> ~/edenOS/Projects/SKALD/; NOSTOS -> ~/edenOS/Projects/NOSTOS/; edenOS Home/Files -> ~/edenOS/Projects/edenOS Embedded/apps/.

PHYSICAL GATE
Exact installed Android version/build and Samsung Quick Settings/SystemUI remain pending. Once known: finalize minSdk/platform adapter; select safe Server Mode toggle integration; ADB-install; verify screen-off service persistence, Wi-Fi, microSD, SMB, SKALD download/remux/serve, NOSTOS Web/local representation, third-party APK install/launch/uninstall and endurance. Do not flash a custom ROM merely to satisfy the APK milestone.

DO NOT DRIFT
Do not redesign EDEN; absorb SKALD/NOSTOS into BIFROST; recreate established Web UIs without need; create a separate senior NOSTOS; modify third-party APK UI; require Play/AI; transcode video on SM-T110; pull smart-home/security scope into this NOSTOS profile; treat placeholders/registration as functionality; or promote without evidence.
