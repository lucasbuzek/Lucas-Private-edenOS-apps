## A. Established product goal; never replace the source
edenPlaces is an independently operable, per-user/per-tenant, permission-aware presentation and access capability inside the existing EDEN/edenOS Online Storage Manager, not a second file-sync engine, app, or 13th portal. Federate providers via BIFROST authenticated connections/provider references; present workspace/files/search through HEIMDALL and ELYSIUM; preserve Dropbox Lite's native independent app; PENELOPE/DeLorean owns verified lineage/recovery. Zero Connections and native accounts retain their established registration authority where applicable. Do not move files to a central store, auto-copy private account content, replace Project Bibles, or require a MacBook for every cloud task.
Acceptance: authorized person on any major browser/device sees and opens actual permitted files and directories from providers available at that moment; their own identities/grants; read-only first; sensitive actions explicit; physical local/NAS files only when their server/endpoint is reachable; mobile browsers function even when native WebMCP is unsupported; a separate OAuth-secured remote MCP endpoint is accessible to supporting clients.

## D. Architecture decision: two complementary user surfaces, not conflation
HUMAN: existing HEIMDALL/ELYSIUM edenPlaces page/PWA, HTTPS, authenticated from any modern browser, fixed-screen/paginated user-recovered UI preference, sources/accounts/folders/tags/search/preview/metadata, readable English then localized SK/other approved user variants. Existing RAVEN visual identity is source-owned; no generic new brand.
AI: HTTPS /mcp with OAuth 2.1/Streamable HTTP; same source-backed provider actions through scoped server API. Browser WebMCP: optional document.modelContext tools that call the human user's same authorized API; no frontend storage secrets; unsupported Safari/mobile gracefully keeps normal UI. Cloudflare Agents adapter is experimental donor, not required prerequisite.

Cloud-file operations work when cloud providers are reachable independently of Macs. On-premises files require independently online NAS/server or authorized owner-endpoint bridge via private Tailscale network/Cloudflare Tunnel, with fail-closed offline indicators. Cloudflare Workers alone are not an always-on SMB/Rclone mount or a persistent local filesystem.

First functional read-only slice:
login/consent -> list provider accounts -> list folder -> search authorized metadata -> preview/open exact file -> denied/expired-grant negative test -> revoke grant and repeat. Each artifact has origin owner, provider account/item ID, canonical/replica/link/cache role, timestamp, offline/materialized truth, real URL or streamed bytes, audit/receipt. A UI displaying fabricated demo files does NOT pass.
Later signed scoped copy/share and delete/change operations require dedicated approval, no-clobber/dry-run/readback/rollback and provider-specific regression. VAULT/CUCKOO and family identities must never leak into ordinary search/cache.
