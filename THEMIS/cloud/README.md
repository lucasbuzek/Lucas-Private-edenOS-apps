# THEMIS Cloud access variant

This is an additive Cloudflare Worker access variant of the **existing THEMIS application**, not a new legal product. The original Python store and prior LKG remain unchanged.

Cloud backend: dedicated SQLite-backed Durable Object per owner; no shared D1 database. 12 canonical record kinds, revision-checked updates, audit trail, checksum snapshots and explicit guarded rollback. Owner-private web UI. The MCP Streamable HTTP endpoint at `/mcp` exposes six record-management tools. It requires an authorized owner session; automated client bearer authentication is not yet configured or tested. The owner web interface uses Cloudflare Access email OTP, with RS256 JWT signature, audience, issuer, expiry and owner email verification inside the Worker. Legacy owner-key sessions remain optional only if independently configured.

Cloudflare free-tier SQLite Durable Objects support is documented at https://developers.cloudflare.com/durable-objects/ . Do not place OWNER_HASH or owner secret in Git. Cloudflare Access owner-only allow policy for `themis-private.lucasravensnest.workers.dev` is configured in the RAVENnest account, and bindings `ACCESS_AUD`, `TEAM_DOMAIN`, `OWNER_EMAIL` are deployed. No owner bearer key or `OWNER_HASH` secret has been set. Private requests without a verified Access assertion or configured owner bearer authorization are denied. Do not add credentials to source. Current cloud authentication requires real owner OTP acceptance testing.

Worker metadata: `main_module:worker.mjs`, second module `ui.js`, `bindings:[{type:'durable_object_namespace',name:'THEMIS_VAULT',class_name:'ThemisVault'}]`, `migrations:{new_tag:'v1',new_sqlite_classes:['ThemisVault']}` for first creation. Do not reapply the new class migration on subsequent updates. Deployed 2026-11-08 with preserved `ThemisVault` namespace and 100% production rollout (Cloudflare deployment `3b4be55e-ded7-45db-b1fb-bbede5aa85d7`).

MCP tools: themis_list_records, themis_get_record, themis_create_record, themis_update_record, themis_list_snapshots, themis_create_snapshot. Server returns JSON-RPC over POST /mcp. No general-purpose AI model or legal authority is falsely claimed. HTTPS + owner authentication is required. This version does not automatically synchronize with the local Python store; the shared record contract is compatible but migrations/sync are not yet acceptance-tested.

Document generation here exports Word-editable HTML `.doc`, not DOCX and not a recreation of the original 19-page 31-Oct document. Real DOCX/full original workflow remains a separate acceptance gate.

Current evidence: live Worker source and UI read back equal this repository; owner allow policy and Durable Object binding verified. External unauthenticated site behavior, actual owner OTP login, record writes and ChatGPT MCP invocation have not yet passed live end-to-end acceptance. Offline Python store and DOCX generation have independently passed local tests; no automatic cloud/local sync is claimed.
