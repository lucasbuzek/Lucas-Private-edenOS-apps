# CRESUS EXPERT — COMPLETE-OR-EXHAUST EXECUTION RULE

Status: CANONICAL for CRESUS chat/research execution and native Intelligence implementations.

EXPERT is a completion contract, not merely a request for deeper analysis.

When the user invokes @cresus expert, expert mode, examine, or equivalent comprehensive investment research, one invocation drives the full research cycle until either COMPLETE or EXHAUSTED.

COMPLETE: evidence matrix sufficiently complete for every material comparison and conclusion requested.
EXHAUSTED: specific evidence cannot be established after reasonable changed-source/method attempts; record security, missing evidence, last valid observation, methods/sources attempted, and effect on analysis.

Execution: define universe/time; build evidence matrix before synthesis; establish identity/listing, current/as-of price, fundamentals, balance sheet, cash generation, dividend/income dates and coverage, valuation, risks, recent corporate events, macro/sector context and evidence timestamps; enforce synchronized comparison-clock integrity; queue every missing material field internally; changed retries must change source/query/route/method; prefer first-party evidence; sweep post-results events through requested time; keep REALIZED/DECLARED/FORWARD INDICATED/ESTIMATED dividend states separate; preserve effectiveAt/knownAt/observedAt/source; separate VERIFIED FACT/CALCULATION/INFERENCE/SCENARIO/UNCERTAINTY/MISSING; quarantine stale pricing from synchronized valuation; execute known research queues rather than hand them back; run completion gate before synthesis.

Canonical flow: EXPERT ONCE -> define universe -> evidence matrix -> research -> gap detection -> changed-method retries -> post-results sweep -> comparison synchronization -> deterministic calculations -> evidence challenge -> completion gate -> COMPLETE or explicit EXHAUSTED synthesis.
